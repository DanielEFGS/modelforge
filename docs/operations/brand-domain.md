# Brand and Domain Gate

## Current status

**ModelForge is a working name, not yet cleared as the final public brand.**

The name is already used by multiple unrelated software/AI/ML projects and businesses. That does not automatically make use impossible, but it creates SEO, package-name, identity and potential trademark risk.

Do not buy a domain merely because one extension is available.

## Gate before domain purchase

### 1. Search collision review

Check:
- Google exact-name results,
- GitHub organization/repositories,
- npm package names/scopes,
- PyPI,
- Product Hunt / developer communities,
- existing SaaS companies,
- app stores if relevant.

### 2. Trademark review

Search relevant trademark databases for target markets/classes. If the project becomes commercially meaningful, professional trademark advice may be warranted.

This blueprint is not legal advice.

### 3. Domain review

Check preferred order:
- `.com`
- `.dev`
- `.app`
- `.io`
- `.tools`

For developer tooling, `.dev` is credible, but the exact name collision matters more than extension preference.

### 4. Social/package handles

Ideally secure a coherent set:
- GitHub org/repo,
- npm scope,
- domain,
- optional social handle.

### 5. Searchability test

A strong final name should:
- be pronounceable,
- be easy to spell after hearing it,
- not be dominated by an unrelated established product,
- have a plausible developer-tool association,
- work as a package/CLI prefix later.

## Domain purchasing strategy

Do not buy many speculative extensions at the beginning.

Recommended:
- buy one primary domain after clearance,
- optionally buy one defensive high-risk variant if inexpensive and justified,
- redirect variants to canonical domain.

## If ModelForge is retained

Brand copy should distinguish product category strongly, e.g.:

> ModelForge — Data Models & Schema Codegen

But a descriptor does not eliminate legal/name collision risk. Complete the gate first.
